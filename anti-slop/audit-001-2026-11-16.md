## HIGH

### 1. R-02 — Em dashes in user-facing text

- **Evidence:** 23 occurrences across `resources/views`, including page titles: `login.blade.php:3` ("Sign in — TraceLess"), `register.blade.php:3`, `verify.blade.php:3`, `layouts/app.blade.php:8`.
- **Why it fails:** the em dash is an explicit Hard Gate ban in agent-written text. Titles render it in the browser tab and the auth screens.

### 2. R-25 — Light-theme contrast fails WCAG AA on two tokens

- **Evidence:** computed relative luminance over the light tokens:
  - `--c-faint` #94A3B8 on white = **2.56:1** (needs 4.5:1); on `--c-surface` #F7F8FA = **2.41:1**
  - `--c-success` #059669 on white = **3.77:1** (AA only for large text)
  - For reference, the other pairs pass: `body` 7.58, `muted` 4.76, `accent` 5.17, white-on-accent 5.17, `warning` 5.02.
- **Why it fails:** `text-faint` is used for small labels, footnotes, muted metadata and nav section headings throughout the app. At 2.56:1 those are unreadable for a large share of users, and this is a regression introduced by the new palette, not inherited slop.
- **Fix direction:** darken `--c-faint` to about #64748B in light mode (4.76:1) and separate "faint" from "decorative border" usage; use a darker green for `--c-success` text (for example #047857, 5.2:1).

### 3. R-24 — Navigation points at a section that does not exist

- **Evidence:** `livewire/settings-page.blade.php:78` links "Compare plans" to `route('home') . '#pricing'`. No element with `id="pricing"` exists on the landing page.
- **Why it fails:** a nav/CTA link with no destination is a broken promise, and this one is on the paid-plan upsell.

### 4. R-26 — The same control is non-functional

- **Evidence:** as above: the "Compare plans" button cannot go anywhere because the target is absent.
- **Why it fails:** every interactive element needs real behaviour or a visible "coming soon" label. This one is a dead button.

### 5. R-40 — Media ships without dimensions, poster, or a load strategy

- **Evidence:** three `<video>` elements with no `width`/`height`/`aspect-ratio` and no `poster`:
  - `landing.blade.php:43` (hero, `preload="auto"`, 7.5 MB file)
  - `layouts/auth.blade.php:28` (backdrop, `preload="metadata"`)
  - `livewire/scan-progress.blade.php:3` (processing loop)
- **Why it fails:** unsized media causes layout shift; the hero video is the largest above-the-fold asset and has no poster, so the first paint is an empty box. `preload="auto"` on a 7.5 MB hero also competes with first render.

### 6. R-39 — Interactive affordance is incomplete

- **Evidence:** `app.css` declares `cursor: pointer` exactly once, on `.btn` (line 134). Plain `<button>` elements (theme toggle, mobile nav trigger, logout, accordion triggers) and `.nav-link` anchors do not declare it; buttons default to the arrow cursor. Icon-only controls do carry `aria-label` (theme toggle, menu, logout), so accessible names are mostly present.
- **Why it fails:** the rule requires every enabled control to show it can be used, set once in the base layer. Only custom-classed buttons currently do.

## MEDIUM

### 7. R-37 — No design direction file and no declared dials

- **Evidence:** the repository has no `DESIGN.md`, and no Design Read (ENERGY / RHYTHM / MOTION) has been declared. The revamp was executed from a chat instruction ("more mature, white/dark template").
- **Why it fails:** without direction the result is a "draft without direction". This is the root cause of findings 8, 12 and 16 (see also #17).

### 8. R-06 — Monospace and wide-tracked uppercase are still doing decorative work

- **Evidence:** 173 `font-mono` occurrences and 47 `uppercase tracking-*` occurrences remain across the views, including `login.blade.php:7` (`<p class="eyebrow">Secure enclave // access</p>`), `landing.blade.php` section labels, and the dashboard's metric captions.
- **Why it fails:** monospace-as-aesthetic and uppercase-with-tracking were the terminal costume. Keeping the technique after removing the theme leaves the same tell with different colours, and no written reason supports either.

### 9. R-09 — Pill badge parked above the H1

- **Evidence:** `landing.blade.php` hero: `<div class="inline-flex items-center gap-2 rounded-full border border-line bg-surface px-3 py-1 text-xs ..."><span class="h-1.5 w-1.5 rounded-full bg-success"></span>Public sources only · Evidence kept for every finding</div>`, directly above the headline.
- **Why it fails:** capsule + dot + label above the headline is the eyebrow-badge pattern. The label restates what the subheadline already says, so it adds a line of reading without a fact.

### 10. R-19 — Status dot that marks no state

- **Evidence:** the same pill's `bg-success` dot, plus `animate-ping`/`animate-pulse` uses in `landing.blade.php` and `scan-progress.blade.php`.
- **Why it fails:** a green dot implies "live" or "healthy". Nothing is live on the marketing page. Endless pulse is motion with no user trigger and no written purpose.

### 11. R-08 — Arrows on most CTAs

- **Evidence:** `arrow_forward` Material Symbol inside the primary buttons on the landing hero, scan-create, verify, dashboard and reports screens.
- **Why it fails:** an arrow on almost every button stops being a directional cue and becomes decoration. No written purpose distinguishes the buttons that need it.

### 12. R-04 — Icon set chosen for availability, not relevance

- **Evidence:** Material Symbols throughout: `radar` for scanning, `hub` for findings, `space_dashboard` for overview, `vpn_key`/`key`, `delete` for removal guidance, `description` for reports. The set is Google's generic icon font, loaded whole from a CDN.
- **Why it fails:** several glyphs are metaphors rather than descriptions (`radar`, `hub`, `space_dashboard`), no relevance is written down, and the font is loaded for every page whether or not it is used.

### 13. R-10 — Glass used on more than the dose cap

- **Evidence:** `backdrop-blur` on the marketing header (`layouts/marketing.blade.php`), the app header (`layouts/app.blade.php`), and the auth aside panel (`lg:backdrop-blur-md`).
- **Why it fails:** the cap is 1-2 elements; three surfaces are frosted at once, so no surface reads as foreground.

### 14. R-05 — Uniform card grid and a four-column footer

- **Evidence:** the "How it works" section (`landing.blade.php`, Step 1 to Step 4) is four identical `ops-card` blocks with identical padding, identical heading size and no hierarchy. The marketing footer is a four-column Product / Trust / Attribution grid.
- **Why it fails:** identical cards and the template footer are named default shapes. Nothing marks the step that matters most, and the footer columns exist because templates have four.

### 15. R-27 — Empty, loading and error states are partial

- **Evidence:** `wire:loading` appears 8 times and `<x-empty-state>` 8 times across 20 inner screens. Findings, removals, reports and settings have no loading affordance on their primary actions. The dashboard's empty state reads "No intelligence nodes detected. Click 'Execute Recon Scan' above." (jargon plus an indirect instruction).
- **Why it fails:** the rule requires the three states per screen, with a cause and a next action. Half the product still assumes the happy path.

### 16. R-15 / R-16 — Copy that says nothing specific to the product

- **Evidence:** "Create your enclave." (`register.blade.php:8`), "Secure enclave // access" (`login.blade.php:7`), "Execute Recon Scan" (`dashboard.blade.php:35`), "No intelligence nodes detected" (`dashboard.blade.php:159`), "ENCLAVE: LOCAL OSINT WORKER ACTIVE // ZERO PASSWORDS QUERIED" (`scan-progress.blade.php:61`).
- **Why it fails:** "enclave", "recon" and "intelligence nodes" are costume vocabulary. They are not generic AI buzzwords from R-16's list, but they fail the same test: the words describe a mood, not what the product does.

## LOW

### 17. R-20 / C-1 — The new interface has no identity of its own

- **Evidence:** light canvas, Inter, Schibsted Grotesk headings, one blue accent, 12px cards. Every element passes individually, but swap the wordmark and the same screens could belong to any B2B SaaS product.
- **Why it fails:** the rule's own test is "if the logo and product name were swapped out, would this still feel unique?" Today, no. Removing the terminal costume removed the slop and left a void, exactly the failure the Liveliness Toolkit warns about. This is the finding that most deserves design time, not a quick patch.

### 18. R-29 / R-11 — Palette and radius are correct but undocumented

- **Evidence:** the palette is neutral + one accent + three semantic status colours (within the cap); radii are 12px cards / 8px controls / pills only for badges (varied, not uniform).
- **Why it fails:** nothing. Recorded here so the next pass does not "fix" what is already right. If a `DESIGN.md` is written (#7), these become the documented rules.

### 19. R-40 — Third-party font and icon stylesheets load render-blocking in `<head>`

- **Evidence:** every layout loads two Google Fonts stylesheets plus the whole Material Symbols font with no `media` trick, `preconnect` only.
- **Why it fails:** the stylesheets are render-blocking third-party requests. Acceptable at low traffic, worth inlining or self-hosting before launch.

## Observations that are not findings

- **R-33 (script patching):** the colour sweep (523 replacements across 26 templates) was executed by a one-off PowerShell script. It edited the source files in place, wrote them as the source of truth, and left no patch script in the repository, so it does not meet the rule's definition of a runtime patcher. Disclosed for transparency.
- **No fabricated metrics found:** 0 occurrences of "500+", "99.9", "10K", "Trusted by", "Get Started", "Learn More", "Seamless", "AI Powered". The fabricated-stats problem from the previous design is gone.
- **Not verifiable here:** anything requiring a rendered measurement, in particular hero-text contrast over the video in light mode (R-25), the mobile 390px pass (R-03), and keyboard traversal (R-32). These must be measured in a browser before launch, not asserted from source.
- **Dead file:** `welcome.blade.php` is unrouted but still ships (176 lines, loads Bunny Fonts). Not a rule violation, just weight.
